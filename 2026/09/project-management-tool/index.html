项目管理工具 - Linear

2026/09/28

一、第一阶段

一开始我是直接使用表格来登记一些待开发的特性的。

但是怎么说呢？状态变更是全手动的

很繁琐。慢慢地我不再去进行记录了，想到什么需要优化的，直接在工具中进行说明，这种也很难再去统计之前做的事情了。因为 commit 历史太多了，可能上千条。

二、第二阶段

这个阶段是找到了一个 jetbrains 开源出来的 youtrack，在本机上安装了 docker 镜像，这个阶段就是使用这个本地界面来跟踪一些待办 issue 的。本机使用的很好，界面也还不错，但是因为本机的存储不足，时常还需要把 docker 给停掉，给其他任务腾出空间。

也是比较麻烦。

并且逐渐加重对 agent 的使用，每次还需要复制粘贴，最后给装了 mcp 工具，这个可以直接读取了，当然完全还是本地操作。

三、第三阶段

这个阶段是 cursor origin 出现了。

在这个出来之前，我的开发进程是堵塞的，至少不是那么的顺畅。

因为受限于 github 网站的速度，这个体验非常不好。

所以日常也不会去进行大量的交互，尝试去访问那是在给自己找不好受。

但是在 cursor origin 出来之后，支持和 github repo 的双向镜像，origin 的访问倒是特别的顺畅，把这个堵塞点给打通了。

四、第四阶段

我在 origin 的 trigger 中发现了一个叫作 Linear 的东西，我之前没有去用过，在国庆前几天，我打开了这个网站，注册了一个账号，尝试着去用了下。当前在使用之前也不知道它是做什么用的。

我觉得可以放弃 youtrack 了，Linear 更好。

用过之后就不想回到表格和 youtrack 了，省去自部署的烦恼。

一个最大的优点就是它可以去批量操作 pr，并且支持和 github issue 的双向同步。

在这个时候我已经开发出来一个需求统一管理中心了，类似于一个前台挂号机，所以的需求起点都是这里。

从这以后我就直接在 Linear 上处理项目事宜了，很方便很方便，交互也很好，同步速度也很快。

cursor 授权 Linear 后，在会话中触发的提示词：

处理下 Linear WW-23 # 这里 WW-23 是 issue 编号

在 Linear 界面复制当前 issue id: command + .。
